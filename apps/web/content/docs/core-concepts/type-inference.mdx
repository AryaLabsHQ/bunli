## How It Works

Bunli uses a revolutionary approach that combines:

1. **Module Augmentation** - Generated types automatically extend the core type system
2. **Command Name Literals** - Using `as const` enables automatic type inference
3. **Standard Schema Integration** - Built-in type extraction from validation schemas
4. **Zero Manual Annotations** - Handlers are automatically typed based on command names

## The Magic: Automatic Type Inference

When you define a command with `as const`, the handler automatically gets the correct types:

```typescript
export default defineCommand({
  name: "deploy" as const, // ← REQUIRED: 'as const' enables type inference
  description: "Deploy the application",
  options: {
    env: option(z.enum(["dev", "staging", "prod"]), {
      description: "Environment to deploy to",
    }),
    dryRun: option(z.boolean().default(false), {
      description: "Run without making changes",
    }),
  },

  // ✨ NO TYPE ANNOTATION NEEDED! ✨
  // flags is automatically typed as { env: 'dev' | 'staging' | 'prod', dryRun: boolean }
  handler: async ({ flags }) => {
    console.log(`Deploying to ${flags.env}`); // ← Full autocomplete!
    if (flags.dryRun) {
      console.log("Dry run mode");
    }
  },
});
```

## Requirements

To use Bunli's automatic type inference, you need:

1. **`as const` Required** - Command names MUST use `as const` for type inference
2. **Generated File Required** - `.bunli/commands.gen.ts` must be in `tsconfig.json`
3. **Type Generation Required** - Codegen must be enabled
4. **No Manual Annotations** - Handler type annotations are automatic

## Command Definition Pattern

### Correct Pattern

```typescript
export default defineCommand({
  name: 'deploy' as const, // ✅ 'as const' required
  options: { ... },
  handler: async ({ flags }) => { // ✅ No annotation needed!
    // flags is automatically typed!
  }
})
```

### Incorrect Pattern

```typescript
export default defineCommand({
  name: 'deploy', // ❌ No 'as const' - no type inference
  options: { ... },
  handler: async ({ flags }: { flags: { env: string } }) => { // ❌ Manual annotation not needed
    // ...
  }
})
```

## Type-Safe Command Execution

With generated types, you can execute commands programmatically. The `execute()` method accepts a command name and optional string array of arguments:

```typescript
import { createCLI } from "@bunli/core";

const cli = await createCLI(config);

// Execute with args array
await cli.execute("deploy", ["--env", "production", "--dry-run"]);

// Execute with options object (for commands with typed options)
await cli.execute("deploy", { env: "production", dryRun: true });
```

> **Note**: The options form provides type-safe options for registered commands, but the `commandName` parameter accepts any `string` at runtime. Always validate command names before calling `execute()` in production code.

## Command Discovery

The generated file provides helper functions for command discovery. Import from the auto-generated `.bunli/commands.gen.ts`:

```typescript
import { cli, listCommands, getCommandApi, findCommandByName, getCommandNames } from "./.bunli/commands.gen";

// List all commands
const commands = cli.list();
console.log(`Total commands: ${commands.length}`);

// Get command metadata by name
const deployApi = getCommandApi("deploy");

// Find a command by name (returns metadata)
const deploy = findCommandByName("deploy");

// Get all command names as a readonly array
const names = getCommandNames();

// Execute via CLI wrapper
const executor = cli.withCLI(myCLI);
await executor.execute("deploy", { env: "production", dryRun: true });
```

The generated store includes:

| Export                        | Returns                                    | Description                       |
| ----------------------------- | ------------------------------------------ | --------------------------------- |
| `cli.list()`                  | `Array<{ name, command, metadata }>`       | All registered commands           |
| `cli.get(name)`               | `Command`                                  | Raw command object                |
| `cli.getMetadata(name)`       | `GeneratedCommandMeta`                     | Metadata for a command            |
| `cli.getFlags(name)`          | `CommandOptions`                           | Flag types for a command          |
| `cli.getFlagsMeta(name)`      | `Record<string, GeneratedOptionMeta>`      | Raw option metadata               |
| `cli.withCLI(cli)`            | `Executor`                                 | CLI wrapper for execution         |
| `findCommandByName(name)`     | `GeneratedCommandMeta`                     | Find command metadata by name     |
| `getCommandNames()`           | `readonly string[]`                        | All command names                 |
| `getCommandApi(name)`         | `GeneratedCommandMeta`                     | Get command metadata               |
| `listCommands()`              | `string[]`                                 | List all command names            |

## Advanced Type Utilities

Bunli exports helper type utilities from `@bunli/core` for extracting and manipulating command types:

```typescript
import type { CommandOptions, RegisteredCommands } from "@bunli/core";

// Extract option type for a specific command
type DeployFlags = CommandOptions<"deploy">;
// → { env: 'dev' | 'staging' | 'prod', dryRun: boolean }

// All registered command names as a union
type AllCommandNames = keyof RegisteredCommands;
// → 'deploy' | 'build' | 'test' | ...

// Extract options type for any registered command
type CmdOpts<T extends keyof RegisteredCommands> = CommandOptions<T>;
```

## Configuration

Enable type generation in your `bunli.config.ts`:

```typescript
export default defineConfig({
  name: "my-cli",
  version: "1.0.0",
});
```

## Generated File Structure

The `.bunli/commands.gen.ts` file contains:

- `commands` — the command objects themselves (named exports for each command)
- `commandMeta` — command metadata including descriptions, options, aliases
- `cli` — a `GeneratedCLI` instance with `list()`, `get()`, `getMetadata()`, `getFlags()`, `withCLI()` methods
- `register(cli?)` — registers commands with a CLI instance
